No random agents

Why exactly 6 agents

Each agent exists because of one specific observed pain point. Test used: each maps 1:1 to a distinct, measurable failure mode in the per-agent telemetry. Merge any two and the pain point returns; a seventh would have nothing distinct to measure.

Agent
Pain point it solves
Why it is not folded in
1Safety Gatekeeper
Single-agent systems burn LLM tokens on hostile queries before anyone notices.
Zero-token rule gate — rejects before the expensive agents are reached.
2Legislative Retriever
A summariser that also retrieves paraphrases the law — the #1 legal-RAG hallucination source.
Only agent with a multi-step tool loop; retrieval accuracy measured on its own.
3Plain-Language Simplifier
Raw statute is unusable for a citizen; the one generative step = the one hallucination point.
Strongest model; followed by a verifier that did not see its reasoning.
4Amendment Analyst
"What changed?" needs structured diffing — a different accuracy measure than summarising.
Own tool (amendment_diff) and own output shape.
5Fact Verifier
Self-verification inside one context inherits its own bias.
Deliberately denied the simplifier's prompt/trace; reports claims_found / claims_missing.
6Citation Finder
An answer without checkable sources is unverifiable.
Uses the network, not the bill corpus — failures independent of retrieval.

03 / Agents
04
Real wire protocols

Not in-process calls — real boundaries

Three claims that are easy to fake and were instead proven with separate processes and wall-clock evidence.

MCP — tools across a process

  • 7 tools served by an MCP stdio server in its own process
  • Client binds bill_lookup, semantic_search, citation_finder
  • server_info reports a PID distinct from the client's
  • Byte-identical results in-process vs over MCP

A2A — agent to agent

  • Google ADK agent served as an A2A 1.0 card on its own process
  • Card at 127.0.0.1:8765/.well-known/agent-card.json
  • CrewAI side is the JSON-RPC client (message/send)
  • Verified by verify_a2a.py — PASS

Parallel — genuinely concurrent

  • Fork-join on a ThreadPoolExecutor: 2 branches
  • Branch A: retriever → simplifier → verifier · Branch B: citation
  • Concurrency proven by wall-clock interval overlap
  • branches_overlapped: true — not a label
Thread-safety work this demanded: locked tool cache, thread-local callback sink so parallel workers' events are attributed, locked quota pacer — three real defects found and fixed.

04 / Protocols
05
Measured, not asserted

50 runs · parallel is 2.6× faster

Same frozen question set, same judges (two model families so no model grades its own family's output). 22 successful runs, 28 provider-quota errors — the errors are logged as such, not hidden.

Mean duration by architecture (11 runs each). Parallel 57.2 s vs sequential 149.4 s on identical questions — the fork-join converts into a real, repeatable latency win, not a theoretical one.

Answer quality

Grounded 4.42 / complete 4.92

Two LLM judges score every answer 1–5. Every passage carries its PRS URL, so the grounded score is anchored to a source a reader can open.

Groundedness by persona. The spread answers "is this robust across who is asking?" — citizen, student, journalist, MP aide and neutral queries all land in the same band.
Duration by persona. No single persona shape blows up latency — the release is uniform rather than driven by a friendly-query case.
5 personas × 4 architectures. Judges: gpt-oss-120b and qwen3-8b — two families, so a model never grades its own family's output.

06 / Quality
07
Evidence, not intention

Eight defects found by running it

Every one of these came from an actual failing run or sweep — not from inspection.

Fixed this cycle

  • UnboundLocalError masking real sweep failures — body initialised in the except branch
  • Serialization crash — raw CrewAI Tool / datetime / UUID objects leaked into the API response; tool names only now
  • WinError 10053/10054 transport aborts — retry class excludes quota so the sweep stops honestly
  • Sampling skew — --per-arch front-sliced one kind; now round-robins

Concurrency + tool boundary

  • Tool-cache race under parallel — now lock-guarded with hit/miss counters
  • Lost callback events — sink is now thread-local, so worker-thread events are attributed
  • MCP wedge on spawn — retry once on transient handshake races; close() safe when unconnected
  • Concurrent-sweep summary clobber — summary regenerated from the full 50-run file
Known limitation, stated plainly: Groq's free tier caps 200k tokens/day/model — refilling at ~2.3 tokens/s, not midnight. 28 of 50 runs hit it. Hence three model buckets and a resumable sweep.
